# Native bound functions in Inkpot

Prosetta's **Native Bound Functions** let a project implement its Ink `EXTERNAL`
declarations in C++ and ship them through Game Engine Sync. Inkpot turns those
modules, and modules written locally in the same shape, into bound functions on
every `UInkpotStory`, checks them against the Prosetta manifest, and exposes the
rest of the Ink runtime's interoperability surface ( variable observers, runtime
error reporting, lookahead flags, fallbacks ) to C++ and Blueprint.

Inkpot runs the InkPlusPlus port of the C# ink runtime, not inkcpp. The binding
model follows inkcpp's `runner->bind("name", &Function)` convention: a plain C++
function is bound by name and the glue derives arity and argument conversion from
its signature.

## What Prosetta ships

| Artifact | Path in the sync mirror / CLI generation | Imported by the Prosetta watch as |
| :-- | :-- | :-- |
| Manifest ( `formatVersion` 1 ) | `native-bindings/manifest.json` | `UProsettaSyncedArtifact` with key `native-bindings` ( `Text` holds the JSON ) |
| One C++ module per shipped module | `native-bindings/cpp/<Module>.cpp` | Staged only; copied with `Prosetta.Watch.ImportNative` |

A shipped module file is a three-line provenance header ( generated-file notice,
`module=... language=cpp project=... scriptId=...`, `prosetta-source-sha256=...` ),
one blank line, then the authored source verbatim:

```cpp
// Generated by Prosetta. Do not edit; changes are overwritten on sync.
// prosetta-native-binding module=Inventory language=cpp project=42 scriptId=12
// prosetta-source-sha256=3f1c...e9

// Native Bound Functions module "Inventory" (C++).
namespace Prosetta::Bindings::Inventory {
    const char* describe_item(const char* item_name, int quantity) {
        return "";
    }

    // @lookaheadSafe
    void play_chime() {
    }
}  // namespace Prosetta::Bindings::Inventory
```

The module is deliberately engine agnostic: parameter types are `int`, `float`,
`bool` and `const char*`; return types are those or `void`; no engine headers,
overloads, variadics, default arguments or entry points. A module excluded in the
manifest ( `status: "excluded"` ) is never served and must be treated as absent.

## Conventions for Prosetta and local modules

Both kinds of module live in one project-owned source directory and follow the same
rules, so the scanner, generator and runtime treat them identically:

```text
Source/MyGame/Prosetta/NativeBindings/
    Inventory.cpp            synced from Prosetta ( never edited; carries the provenance header )
    Inventory.Bindings.cpp   generated loader
    Cheats.cpp               local module: namespace Prosetta::Bindings::Cheats { ... }
    Cheats.Bindings.cpp      generated loader
```

Rules:

- One file per module, `namespace Prosetta::Bindings::<Module> { ... }`, module name
  `^[A-Za-z_][A-Za-z0-9_]*$` and at most 64 characters, unique ignoring case.
- Every free function in the namespace implements the Ink `EXTERNAL` of the same name
  with the same parameter count.
- Mark a function Ink may call during lookahead ( no side effects ) with
  `// @lookaheadSafe` on the line above its signature. Anything that changes game
  state stays unmarked; the Ink VM then calls it exactly once, after the line is
  committed.
- A returned `const char*` is copied before the call returns, so a literal or a
  static buffer is enough.
- Local modules need no provenance header. They may include standard headers but
  not engine headers; keep engine access in a separate file the module calls into.

## The loader

A module registers itself through a small Inkpot-side loader that forward declares
its functions and calls the registration macros. The editor writes it; it is safe
to hand write for a local module:

```cpp
// Generated by Inkpot. Do not edit; regenerate with Prosetta.NativeBindings.Generate.
// inkpot-native-binding module=Inventory source=prosetta authored-sha256=3f1c...e9
#include "Inkpot/NativeBindings/InkpotNativeBinding.h"

namespace Prosetta::Bindings::Inventory
{
	const char* describe_item(const char* item_name, int quantity);
	void play_chime();
}

INKPOT_NATIVE_BINDING_MODULE_BEGIN(Inventory, EInkpotNativeBindingSource::Prosetta, "3f1c...e9")
	INKPOT_NATIVE_BINDING(describe_item, false)
	INKPOT_NATIVE_BINDING(play_chime, true)
INKPOT_NATIVE_BINDING_MODULE_END(Inventory)
```

The macros build an `FInkpotNativeBindingModule` and add it to the process-wide
`FInkpotNativeBindingRegistry` from a static initialiser, so every module linked
into the game is known before the first story begins. Hot reload and Live Coding
re-register by name; a stale registration cannot remove a newer one.

Template glue ( `Inkpot/NativeBindings/InkpotNativeBindingGlue.h` ) converts Ink
values to the C++ parameter types with the same lenient coercion Ink applies
( int / float / bool interchange, numbers formatted for strings ) and reports an
error for lists or divert targets. Wrong argument counts are logged and return
nothing.

## Editor workflow

1. Sync. With the Prosetta watch, accept a generation, then copy and validate the
   staged C++ in one step:

   ```text
   Prosetta.Watch.ImportNative "Project42/Live_<scope-hash>" "/abs/Source/MyGame/Prosetta/NativeBindings" generate
   ```

   With the sync CLI mirror ( `Saved/Prosetta/native-bindings/cpp/*.cpp` ), copy the
   `.cpp` files into the source directory yourself, then:

   ```text
   Prosetta.NativeBindings.Scan "/abs/Source/MyGame/Prosetta/NativeBindings" "/abs/Saved/Prosetta/native-bindings/manifest.json"
   Prosetta.NativeBindings.Generate "/abs/Source/MyGame/Prosetta/NativeBindings" "/abs/Saved/Prosetta/native-bindings/manifest.json"
   ```

   The manifest argument is optional; when omitted the editor uses
   `Saved/Prosetta/native-bindings/manifest.json` if it exists. `Scan` validates
   and reports without writing; `Generate` also writes `<Module>.Bindings.cpp` for
   every valid module whose loader changed.

2. Rebuild the game module.

3. Check what is registered and whether it matches the manifest:

   ```text
   Prosetta.NativeBindings.List
   Prosetta.NativeBindings.Audit ["/abs/native-bindings/manifest.json"]
   ```

   `Audit` also audits every running story: the `EXTERNAL`s it calls versus what
   is bound. Both commands are available in game builds as well as the editor.

Validation mirrors Prosetta's C++ validator and adds sync checks:

| Diagnostic | Meaning |
| :-- | :-- |
| `cpp-namespace`, `cpp-namespace-missing` | Not exactly one `namespace Prosetta::Bindings::<Module>` |
| `cpp-engine-header` | An engine SDK header is included |
| `cpp-return-type`, `cpp-parameter-type` | A type outside int / float / bool / const char* ( / void ) |
| `cpp-overload`, `cpp-variadic`, `cpp-default-parameter`, `cpp-entry-point`, `cpp-braces` | Shape errors |
| `cpp-no-functions` | Warning: the module binds nothing |
| `provenance-sha-mismatch` | A shipped file was edited after sync |
| `provenance-module`, `provenance-language` | The header disagrees with the file name or is not C++ |
| manifest errors | Module excluded by Prosetta, local bytes differ from the manifest sha, function set or arity differs, or arity differs from the Ink `EXTERNAL` |

The generator refuses to write a loader for a module with errors. Manifest
lookahead flags win over source annotations when the two disagree ( reported as a
warning ).

## Runtime behaviour

`UInkpotSettings` ( Project Settings > Plugins > Inkpot ):

| Setting | Default | Effect |
| :-- | :-- | :-- |
| `bAutoBindNativeFunctions` | on | `BeginStory` ( and hot reload ) binds every registered function the story calls. Existing Blueprint / C++ bindings are never replaced. |
| `bValidateExternalBindingsOnFirstContinue` | on | The first `Continue` logs an error for each `EXTERNAL` the story calls that is still unbound. The VM aborts when it reaches one, so this turns a crash into a readable error. |
| `bAllowExternalFunctionFallbacks` | off | An unbound `EXTERNAL` diverts to an Ink function of the same name when one exists ( Ink's `allowExternalFunctionFallbacks` ). |
| `bLogStoryErrors` | on | Runtime errors and warnings reported by the VM are logged under the `Inkpot` category as well as broadcast. |

`UInkpotStory` API ( Blueprint and C++ unless noted ):

- `GetDeclaredExternalFunctions()` – every `EXTERNAL` the compiled story calls, with
  arity and whether an Ink fallback exists.
- `IsExternalFunctionBound(Name)`, `ValidateExternalBindings(OutUnbound, bLogErrors)`.
- `BindRegisteredNativeFunctions(ModuleFilter, bOverrideExisting)` – returns an
  `FInkpotNativeBindingReport` ( bound, already bound, arity mismatches, unbound ).
- `BindNativeFunction(Name, &Function, bLookaheadSafe)` – C++ only, inkcpp style
  direct binding of a free function.
- `SetAllowExternalFunctionFallbacks(bool)`.
- `SetOnAnyVariableChange(Delegate)` / `ClearAnyVariableChange(Owner)` – observe
  every global variable; `GetGlobalVariableNames()`.
- `ObserveVariableNative(Variable, Lambda)`, `ObserveAllVariablesNative(Lambda)`,
  `RemoveVariableObserver(Handle)` – C++ observers owned by the story.
- `OnStoryError` ( Blueprint event ) and `OnStoryError()` ( C++ multicast ) – runtime
  errors and warnings the VM reports after a `Continue`. Errors the port raises
  through its exception substitute are still logged by InkPlusPlus.

`UInkpotNativeBindingLibrary` ( Blueprint function library ):

- `GetRegisteredModules()`, `FindRegisteredFunction()`, `GetDuplicateFunctionNames()`.
- `ParseManifest()`, `LoadManifestFile()`, `LoadManifestFromArtifact()`,
  `LoadManifestFromGeneration()`, `GetDefaultMirrorManifestPath()`.
- `AuditRegistryAgainstManifest(Manifest)` – findings with stable codes
  ( `module_not_registered`, `function_missing`, `arity_mismatch`,
  `lookahead_mismatch`, `source_sha_mismatch`, `module_not_shipped`,
  `module_not_in_manifest`, `function_extra`, `external_unbound`,
  `duplicate_function` ).
- `AuditStory(Story, Manifest)` – adds the story's own unbound `EXTERNAL`s.

Binding order: the first registered module ( sorted by name ) that implements an
`EXTERNAL` wins; `GetDuplicateFunctionNames` and the audit flag collisions. Only
functions the story calls are bound, so unrelated modules cost nothing.

## Tests

`Inkpot.Prosetta.NativeBindings.*` ( editor automation ): registry and glue,
runtime binding / observers / lookahead on a compiled story with `EXTERNAL`s,
manifest parsing and audit, the source scanner, and the loader generator.
`python3 Scripts/agent-verify.py` runs them with the rest of `Inkpot.Prosetta`.
